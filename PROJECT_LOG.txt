================================================================================
SECTION 1 — PROJECT OVERVIEW
================================================================================

A university attendance system with two portals:
  - ADMIN   : Manages departments, sections, teachers, students, reports
  - TEACHER : Marks attendance, views students, sees history

Auth model (NOT Google login):
  - Admin creates teacher accounts from the admin portal
  - System auto-generates a 6-digit ID and random password
  - Trick: Firebase Auth requires email, so we use `<id>@uniattend.local`
  - Teacher can change password after first login
  - Admin never sees the new password

Database schema:
  - departments         (structure: CS, EE, BBA)
  - sections            (structure: CS-3A, CS-3B, EE-2A)
  - students            (later)
  - teachers            (people)
  - subjects            (later)
  - enrollments         (later, many-to-many student<->subject)
  - attendanceSessions  (later)
  - attendanceRecords   (later, subcollection of sessions)
  - timeSlots           (later)
  - admins
  - imports             (later, audit trail)
  - auditLogs           (later)

SECTION 4 — FILES WRITTEN (WHAT EACH ONE DOES)
================================================================================

--- lib/main.dart ---
  Initializes Flutter binding + Firebase + providers. Launches LoginScreen.

--- lib/services/auth_service.dart ---
  - login(id, password) → role ('admin' | 'teacher') or null
  - logout()
  - createTeacher(fullName, contactEmail) → auto-generates ID + password
      * Uses secondary Firebase app so admin stays logged in

--- lib/services/department_service.dart ---
  - createDepartment(id, name)
      * Uses uppercase ID as document ID (e.g., "CS")
      * Rejects duplicates
  - getAllDepartments() → List<Department>

--- lib/models/department.dart ---
  Data class with fromFirestore factory

--- lib/providers/auth_provider.dart ---
  State: isLoading, errorMessage, role. Methods: login, logout.

--- lib/screens/login_screen.dart ---
  6-digit ID + password. Routes to correct dashboard by role.

--- lib/screens/admin_dashboard_screen.dart ---
  Two cards: Departments + Teachers. Logout button.

--- lib/screens/departments_list_screen.dart ---
  Lists all departments. FAB → Add Department. Pull-to-refresh.

--- lib/screens/add_department_screen.dart ---
  Form: code (max 5 letters) + full name. Validates input.

--- lib/screens/teachers_list_screen.dart ---
  StreamBuilder on teachers collection. FAB → Add Teacher.

--- lib/screens/add_teacher_screen.dart ---
  Form: Full Name + Contact Email. Shows generated credentials dialog.

--- lib/screens/teacher_dashboard_screen.dart ---
  Placeholder + logout icon.

--- .github/workflows/ci.yml ---
  Runs on push/PR to main: java 17, flutter stable, pub get,
  analyze, test.

SECTION 7 — GIT + GITHUB WORKFLOW (PROFESSIONAL)
================================================================================

GOLDEN RULE: Never commit directly to main. Use feature branches + PRs.

--- START A NEW FEATURE ---
  git checkout main
  git pull origin main
  git checkout -b feature/short-description

--- BEFORE COMMITTING ---
  flutter analyze
  flutter test

--- COMMIT + PUSH ---
  git add .
  git commit -m "feat: description"
  git push -u origin feature/short-description

--- ON GITHUB ---
  → Open repo → "Compare & pull request" → fill title + description
  → Create pull request → wait for CI ✅
  → Merge → Confirm merge → Delete branch

--- SYNC LOCAL BACK ---
  git checkout main
  git pull origin main
  git branch -D feature/short-description

--- RECOVERY COMMANDS ---
  git restore <file>              discard local changes
  git checkout -f main            force switch
  git reset --soft HEAD~1         undo last commit, keep changes
  git branch -D branch-name       force delete branch
  git remote remove origin        remove broken remote
  git remote add origin <URL>     add new remote

--- COMMIT TYPES ---
  feat / fix / chore / docs / refactor / style / test
