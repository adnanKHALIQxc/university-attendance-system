================================================================================
SECTION 1 — PROJECT OVERVIEW
================================================================================

A university attendance system with two portals:
  - ADMIN   : Manages teachers, sections, students, subjects, reports
  - TEACHER : Marks attendance, views students, sees history

Auth model (NOT Google login):
  - Admin creates teacher accounts from the admin portal
  - System auto-generates a 6-digit ID and random password
  - Trick: Firebase Auth requires email, so we use `<id>@uniattend.local`
  - Teacher can change password after first login
  - Admin never sees the new password

Database schema (designed, not all implemented yet):
  - departments
  - sections
  - students
  - teachers
  - subjects
  - enrollments         (many-to-many: student <-> subject)
  - attendanceSessions  (one per class held)
  - attendanceRecords   (subcollection of sessions — per student)
  - timeSlots
  - admins
  - imports             (audit trail for Google Form / CSV imports)
  - auditLogs

SECTION 4 — FILES WRITTEN (WHAT EACH ONE DOES)
================================================================================

--- lib/main.dart ---
  - Initializes Flutter binding + Firebase
  - Wraps app in MultiProvider (AuthService + AuthProvider)
  - Launches LoginScreen

--- lib/services/auth_service.dart ---
  - login(id, password)   → returns role ('admin' | 'teacher') or null
      * Builds email as `<id>@uniattend.local`
      * Signs in via Firebase Auth
      * Reads Firestore to detect role
  - logout()
  - createTeacher(fullName, contactEmail)
      * Uses SECONDARY Firebase app (so admin stays logged in)
      * Generates 6-digit ID + 8-char random password
      * Creates Auth user, writes Firestore doc
      * Returns (id, password) to show admin
  - _generatePassword()  → secure random 8 chars (letters + digits)

--- lib/providers/auth_provider.dart ---
  - Holds: isLoading, errorMessage, role
  - login(id, password) → bool
  - logout()
  - isAdmin / isTeacher getters

--- lib/screens/login_screen.dart ---
  - TextFields for 6-digit ID + password
  - On login success → routes to AdminDashboard or TeacherDashboard

--- lib/screens/admin_dashboard_screen.dart ---
  - Shows "Add New Teacher" button
  - Logout icon (top-right) → calls logout + navigates to LoginScreen

--- lib/screens/teacher_dashboard_screen.dart ---
  - Placeholder text ("coming soon")
  - Logout icon

--- lib/screens/add_teacher_screen.dart ---
  - Form: Full Name + Contact Email
  - Calls createTeacher
  - Shows dialog with generated ID + password

--- .github/workflows/ci.yml ---

  - Steps: set up Java 17, set up Flutter, flutter pub get,

SECTION 7 — GIT + GITHUB COMMANDS (MASTER REFERENCE)
================================================================================

--------------------------------------------------------------------------------
 7.1 — ONE-TIME SETUP (per machine)
--------------------------------------------------------------------------------

  git config --global init.defaultBranch main
    → Makes every new repo default to 'main' instead of 'master'

--------------------------------------------------------------------------------
 7.2 — FIRST-TIME SETUP (per project)
--------------------------------------------------------------------------------

  git init
    → Start tracking this folder as a Git repo

  git add .
    → Stage all files for the next commit

  git commit -m "chore: initial project setup"
    → Create the first commit

  git branch -M main
    → Rename the default branch from 'master' to 'main'

  git remote add origin https://github.com/USERNAME/REPO.git
    → Link local repo to GitHub

  git push -u origin main
    → Push to GitHub + remember the upstream (so future 'git push' works alone)

--------------------------------------------------------------------------------
 7.3 — DAILY WORKFLOW (feature branch → PR → merge)
--------------------------------------------------------------------------------

  STEP 1: Start fresh from main
  ----------------------------------
  git checkout main
  git pull
  git checkout -b feature/short-description

  STEP 2: Make changes, then run checks locally
  ----------------------------------
  flutter analyze
  flutter test

  STEP 3: Stage and commit
  ----------------------------------
  git add .
  git commit -m "feat: describe what you added"

  STEP 4: Push the branch
  ----------------------------------
  git push -u origin feature/short-description

  STEP 5: On GitHub
  ----------------------------------
  → Open the repo in browser
  → Click "Compare & pull request" (yellow banner appears automatically)
  → Fill in title + description
  → Click "Create pull request"
  → Wait for CI ✅
  → Click "Merge pull request" → "Confirm merge" → "Delete branch"

  STEP 6: Sync local back to main
  ----------------------------------
  git checkout main
  git pull origin main
  git branch -D feature/short-description

--------------------------------------------------------------------------------
 7.4 — CHECKING STATE (run these often)
--------------------------------------------------------------------------------

  git status
    → What files changed, what's staged, what's not

  git branch
    → List local branches (* = current)

  git log --oneline -10
    → Last 10 commits in short form

  git remote -v
    → Show the remote URL(s)

  git diff
    → Show unstaged changes line-by-line

  git diff --staged
    → Show what's about to be committed

--------------------------------------------------------------------------------
 7.5 — FIXING MISTAKES
--------------------------------------------------------------------------------

  git restore <file>
    → Discard local changes to a file (revert to last commit)
    Example: git restore .github/workflows/ci.yml

  git checkout -f main
    → Force-switch to main even if you have uncommitted changes

  git reset --soft HEAD~1
    → Undo the last commit but keep the changes staged

  git branch -D branch-name
    → Force-delete a branch (use when branch is already merged remotely)
    Note: Capital -D — lowercase -d will refuse unmerged branches

  git restore --source=HEAD~1 -- <file>
    → Restore a single file to how it was 1 commit ago

--------------------------------------------------------------------------------
 7.6 — TROUBLESHOOTING REMOTE ISSUES
--------------------------------------------------------------------------------

  If push fails with "Repository not found":
  ----------------------------------
  git remote remove origin
  git remote add origin https://github.com/USERNAME/REPO.git
  git remote -v               (verify)
  git push -u origin main

  If pull complains about missing ref:
  ----------------------------------
  git pull origin main        (be explicit about the branch)

--------------------------------------------------------------------------------
 7.7 — COMMIT MESSAGE CONVENTION (Conventional Commits)
--------------------------------------------------------------------------------

  Format: <type>: <short description>

  feat     : new feature for the user
             e.g., "feat: add manage sections screen"

  fix      : bug fix
             e.g., "fix: replace print with debugPrint"

  chore    : maintenance (deps, config, CI)
             e.g., "chore: add GitHub Actions CI workflow"

  docs     : documentation changes
             e.g., "docs: add project development log"

  refactor : code cleanup without changing behavior
             e.g., "refactor: extract login form into widget"

  style    : formatting only, no code change
  test     : adding or fixing tests
